# Book-to-Note: 도서 학습 노트 에이전트

책 제목(+저자)을 입력받아 웹 검색으로 핵심 내용을 수집하고, 구조화된 학습 노트를 자동 생성하여 옵시디언 볼트에 저장합니다.

## 파이프라인 개요

```
책 제목 수신 → 메타데이터 검색 → 장르 판별 → 핵심 내용 수집 (서브에이전트) → 노트 생성 → 보충자료 수집 → 내부 링크 생성 → 옵시디언 저장
```

---

## Step 1: 입력 수집

사용자로부터 다음을 수집하세요:

**필수:**
- 책 제목 (한국어 또는 영어)

**선택 (자동 감지 실패 시 요청):**
- 저자명
- 장르 힌트: tech / knowledge / selfhelp
- 독서일 (기본값: 오늘)
- 특별히 집중할 챕터나 주제

## Step 2: 메타데이터 검색

### 도서 정보 수집

WebSearch로 다음을 순서대로 검색:

1. `"{책 제목}" {저자} 책 요약 핵심 내용`
2. `"{책 제목}" book summary key ideas author`
3. `"{책 제목}" 서평 리뷰`

→ 다음 정보를 추출:
- **제목** (원제 + 번역서 제목)
- **저자** (원저자명 + 한국어 표기)
- **출판연도**
- **페이지 수** (대략적)
- **분야/카테고리**
- **한 줄 소개** (출판사 또는 서평에서)

### 핵심 내용 수집 전략

WebSearch로 최소 5회 이상 검색하여 다각도로 정보를 수집:

| 검색 순서 | 검색어 패턴 | 수집 목표 |
|-----------|-----------|----------|
| 1차 | `"{책 제목}" 핵심 내용 요약 챕터별` | 전체 구조, 챕터 목차 |
| 2차 | `"{책 제목}" book summary chapter by chapter` | 챕터별 핵심 아이디어 |
| 3차 | `"{책 제목}" key ideas takeaways` | 핵심 메시지, 주요 개념 |
| 4차 | `"{책 제목}" {저자} interview TED talk` | 저자 관점, 핵심 주장의 배경 |
| 5차 | `"{책 제목}" criticism review analysis` | 비판적 시각, 한계점 |
| 6차 (선택) | 책의 핵심 개념/용어 개별 검색 | 개념 보강, 학술적 근거 |

> [!important] 검색 결과 처리 원칙
> - 여러 출처에서 공통으로 언급하는 내용을 우선 반영
> - 구체적 연구/사례/수치를 최대한 보존
> - 출처마다 다른 해석이 있으면 복수 관점 병기
> - 검색 결과가 부족하면 사용자에게 알리고 진행 여부 확인

## Step 3: 장르 판별

수집된 정보(제목, 저자, 분야, 핵심 내용)를 기반으로 판별:

| 장르 | 시그널 |
|------|--------|
| **tech** | 프로그래밍, 아키텍처, 시스템 설계, API, 알고리즘, 데이터, AI/ML, 개발 방법론, 소프트웨어 |
| **knowledge** | 과학, 역사, 경제, 심리학, 철학, 사회학, 정치, 연구, 논문, 교양 |
| **selfhelp** | 습관, 생산성, 마인드셋, 자기계발, 리더십, 커뮤니케이션, 성공, 동기부여, 커리어 |

확신도 70% 미만이면 사용자에게 확인하세요.

## Step 4: 핵심 내용 분석 (서브에이전트)

### 서브에이전트 분석

Task 도구로 서브에이전트를 실행하여 수집된 정보를 구조화합니다.

서브에이전트에게 다음을 요청하세요:

> 수집된 도서 정보를 분석하여 JSON 형태의 중간 결과물을 생성하세요.
>
> 1. **챕터 분절**: 책의 핵심 논점 기준으로 3~6개 챕터, 각 챕터에 제목/난이도(🟢🟡🔴)
> 2. **챕터별 분석**: 핵심 주장/개념, 근거/사례(구체적 수치 보존), 용어, 코드(tech), 실천법(selfhelp), 비유, 흔한 오해
> 3. **전체 분석**: 한 줄 핵심, 4~6문장 개요, 마인드맵 구조, 암기 포인트(★ 중요도), 용어 사전, 종합 정리, 셀프테스트 질문

서브에이전트 결과물은 JSON 형태로 반환받으세요. 상세 JSON 스키마는 `.claude/skills/book-to-note/references/sub-agent-schema.md`를 참조.

## Step 5: 노트 생성

장르에 따라 해당 프롬프트 참조 파일을 읽고 노트를 생성하세요:

| 장르 | 참조 파일 | 템플릿 |
|------|----------|--------|
| tech | `.claude/skills/book-to-note/references/prompt-tech.md` | `d. Templates/Book-Note-Tech-Template.md` |
| knowledge | `.claude/skills/book-to-note/references/prompt-knowledge.md` | `d. Templates/Book-Note-Knowledge-Template.md` |
| selfhelp | `.claude/skills/book-to-note/references/prompt-selfhelp.md` | `d. Templates/Book-Note-Selfhelp-Template.md` |

### 적용 프레임워크 (v2.0)

| 프레임워크 | 적용 위치 | 역할 |
|-----------|----------|------|
| **SQ3R** | 전체 흐름 | Survey(Book on a Page)→Question(읽기 전 질문)→Read(Part별 내용)→Recite(셀프 테스트)→Review(복습 로그) |
| **Cornell 5R** | 각 Part 내부 | 핵심 질문(Cue Column) + 내용(Notes) + 한 줄 요약(Summary) |
| **Bloom's Taxonomy** | 이해도 체크 & 셀프 테스트 | 기억→이해→적용→분석→평가 단계별 질문 설계 |
| **Feynman Technique** | "비유로 이해하기" | 설명할 수 없으면 이해한 게 아님 |
| **Progressive Sum. L5** | "Book on a Page" | 전체를 한 페이지로 압축 |
| **Zettelkasten** | 용어 사전 & 내 생각 | 볼트 내부 `[[]]` 링크로 지식 네트워크 형성 |

### 핵심 작성 원칙

1. **책의 구조를 따른다**: 임의로 챕터를 재구성하지 않고, 원서의 Part/Chapter 구조를 그대로 반영
2. **재구성, 단순 요약 금지**: 학습 가능한 구조로 변환. 책을 읽지 않은 사람도 핵심을 파악할 수 있되, 책을 읽은 사람에게는 복습 도구가 되어야 함
3. **밀도 우선**: 모든 문장에 정보, 빈 말 없이
4. **연결 강조**: 파트 간 "왜 이 순서인지" 명시적 연결
5. **구체성 보존**: 연구 수치, 사례 디테일, 코드 원문 최대한 보존
6. **학습 과학 내장**: Cornell(인출), Bloom(단계적 질문), Feynman(비유), 간격 반복(복습 로그)
7. **웹 검색 기반 보강**: 책 원문 접근 없이도 최대한 풍부한 내용 구성

### 형식 규칙

- **OFM**: `[[]]` 내부 링크, `> [!warning]` callout, Mermaid 다이어그램
- **난이도**: `🟢 기초` `🟡 중급` `🔴 심화`
- **목차**: `[[#섹션명]]` 링크 (필수)
- **분량**: 본문 약 10,000자 (8,000~12,000자)
- **인용**: 저자 직접 인용은 `> ` blockquote + 출처 표기

### 금지 사항

- ❌ "이 책에서는~" 같은 메타 서술
- ❌ 웹 검색으로 확인되지 않은 내용 추가 (환각)
- ❌ 빈 문장, 불필요한 연결어
- ❌ 저작권을 침해하는 장문의 원문 인용

## Step 6: 보충자료 수집

노트의 핵심 용어/개념 중 최대 8개를 선정하여 WebSearch로 검색:

| 장르 | 검색 우선순위 |
|------|-------------|
| tech | 공식문서 → GitHub → 튜토리얼 → 심화 아티클 |
| knowledge | 원본 연구/논문 → 관련 도서 → 관련 강연/영상 |
| selfhelp | 저자 인터뷰/강연 → 관련 도서 → 실천 가이드 |

결과를 필터링하여 **보충자료 섹션** (3~5개)과 **용어 사전 보강**에 반영하세요. 각 자료에 "이 노트의 어떤 부분을 보완하는지"를 명시.

## Step 7: 내부 링크 생성

`mcp__obsidian__search_notes`로 볼트 내 관련 노트를 검색하세요:

1. **용어 사전**: 각 용어로 검색 → 관련 노트 발견 시 `[[노트명]]` 추가
2. **"내 생각 & 연결"**: 핵심 주제로 검색 → 관련 노트 2~3개 연결, 연결 이유 기재
3. **본문**: 기존 노트의 주제가 언급되면 자연스럽게 `[[]]` 링크

**규칙**: 볼트에 실제 존재하는 노트만 링크. 빈 링크 금지. 한 노트당 2~10개.

## Step 8: 옵시디언 저장

### 파일명 생성

```
Book-{genre}-{YYMMDD}-{제목축약}.md
```
- 제목축약: 핵심 키워드 2~4개, 하이픈 연결, 30자 이내

### 프론트매터 조립

```yaml
---
type: book-note
genre: {tech|knowledge|selfhelp}
source: "{책 제목}"
author: "{저자명}"
year: {출판연도}
date_read: {YYYY-MM-DD}
date_created: {오늘 날짜}
tags:
  - book-note
  - {장르}
  - {주제 태그 3~5개}
review:
  - null
  - null
  - null
confidence: null
status: processed
version: "1.0"
---
```

### 저장

1. **중복 체크**: `mcp__obsidian__search_notes`로 동일 책 노트 존재 여부 확인
   - 존재 시 → 사용자에게 덮어쓰기 확인
2. **저장**: `mcp__obsidian__write_note(path="Book-to-Note/{파일명}.md", content, frontmatter)`
3. **검증**: `mcp__obsidian__read_note`로 저장 확인

### 결과 보고

사용자에게 다음을 보고하세요:
- 저장된 노트 경로와 링크
- 연결된 내부 링크 목록
- 보충자료 요약
- 웹 검색으로 수집한 정보의 한계 안내 (원문 미참조)
- 다음 복습 일정 안내 (+1일, +7일, +30일)

## 에러 핸들링

| 에러 | 대응 |
|------|------|
| 검색 결과 부족 | "이 책에 대한 정보가 충분하지 않습니다" → 사용자에게 추가 정보 요청 |
| 장르 불확실 | 사용자에게 선택 요청 |
| Obsidian MCP 실패 | "Obsidian이 실행 중인지 확인해주세요" |
| 중복 파일명 | 사용자 확인 후 덮어쓰기 또는 번호 추가 |
| 동명의 다른 책 | 저자/출판사 정보로 구분, 사용자에게 확인 |
