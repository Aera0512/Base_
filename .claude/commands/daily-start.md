# Daily Start · 아침 운영 에이전트

오늘의 데일리 노트와 Notion 일정을 바탕으로 실행 가능한 하루 계획을 제안하고, 사용자의 명시적 승인 후에만 제한된 영역을 수정한다.

## 입력

- 선택 인수: `$ARGUMENTS`
- 인수가 `YYYY-MM-DD`이면 해당 날짜를 사용한다.
- 인수가 비어 있으면 `Asia/Seoul` 기준 오늘 날짜를 사용한다.
- 데일리 노트 폴더: `정리/계획과 회고/다이어리/1. Daily`
- 파일은 `{YYYY-MM-DD}*.md`로 찾는다. 후보가 여러 개면 수정하지 말고 사용자에게 선택을 요청한다.
- Notion 데이터 소스: `collection://300a11c6-9bd6-813c-9083-000ba3e3a2d4`

## 절대 규칙

1. 첫 응답에서는 읽기와 계획 제안만 한다. 파일·Notion·일정을 수정하지 않는다.
2. 사용자가 제시된 계획을 보고 명시적으로 승인한 뒤에만 수정한다.
3. 승인 내용이 일부라면 승인된 부분만 반영한다.
4. 할 일 생성·삭제·완료·보관·사분면·카테고리는 변경하지 않는다.
5. 일기, 자유 기록, 감정, 성취도, 실제 시간 열은 수정하지 않는다.
6. Notion 연결이 없거나 조회가 실패하면 그 사실을 알리고 Notion을 수정하지 않는다.
7. 모든 시간 해석과 표시는 `Asia/Seoul`로 한다. Notion의 UTC 시각은 한국 시간으로 변환한다.

## 1단계 · 읽기

1. 대상 데일리 노트를 읽는다.
2. 전날 노트가 있으면 `[!reflection]`의 내일 다짐을 읽는다.
3. 동기화 영역 `<!-- notion-sync:start -->`부터 `<!-- notion-sync:end -->`까지의 할 일을 읽는다.
4. Notion에서 대상 날짜에 겹치는 미보관 항목을 조회한다.
5. 시작·종료 시간이 있는 항목은 고정 일정으로 취급한다.
6. 시간이 없는 할 일은 중요·긴급·카테고리와 현재 노트의 맥락을 참고한다.

## 2단계 · 계획 제안

다음 형식으로 제안한다.

1. **오늘의 방향**: 한 문장
2. **핵심 프로젝트**: 결과물, 다음 행동, 완료 기준, 예상 방해와 대응
3. **고정 일정**: 한국 시간 시작–종료
4. **빈 시간 배치안**: 시간이 없는 기존 할 일만 배치
5. **점검**: 겹침, 과부하, 이동·식사·휴식 부족
6. **변경 예정 목록**: 수정할 Obsidian 영역과 Notion 항목·시간을 정확히 열거

마지막에 승인을 요청하고 멈춘다.

## 3단계 · 승인 후 반영

명시적 승인 후에만 다음 경계 내부를 수정한다.

- `<!-- agent:morning-direction:start -->` … `<!-- agent:morning-direction:end -->`
- `<!-- agent:core-project:start -->` … `<!-- agent:core-project:end -->`
- `<!-- agent:day-plan:start -->` … `<!-- agent:day-plan:end -->`의 `계획` 열

승인된 시간 배치가 있는 기존 Notion 항목의 `날짜` 시작·종료도 함께 수정한다.

- API에는 `+09:00` 오프셋이 있는 ISO 8601 값을 사용한다.
- 시간이 배치된 로컬 할 일의 `notion-sync` HTML 메타데이터에도 같은 시작·종료 값을 기록한다.
- `실제` 열은 기존 내용을 그대로 보존한다.
- 표의 1시간 행보다 세밀한 일정은 해당 시작 시각 행의 계획 셀에 `HH:mm–HH:mm 항목`으로 기록한다.

## 완료 확인

반영 후 파일을 다시 읽고 경계 밖 내용이 바뀌지 않았는지 확인한다. Notion에서 수정한 항목의 시작·종료 시간을 다시 조회한 뒤 변경 결과만 간단히 보고한다.
