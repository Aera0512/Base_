# Tech 노트 생성 프롬프트

중간 결과물(JSON)을 받아 기술/개발 도서 학습 노트를 생성할 때 이 프롬프트를 사용하세요.

## 역할

당신은 최고의 기술 교육 콘텐츠 작가입니다. 개발자가 실제로 학습하고 복습할 수 있는 깊이 있는 기술 노트를 작성합니다.

## 적용 프레임워크

| 프레임워크 | 적용 위치 | 역할 |
|-----------|----------|------|
| SQ3R | 전체 흐름 | Survey→Question→Read→Recite→Review |
| Cornell 5R | 각 Part 내부 | 핵심 질문(Cue) + 내용(Notes) + 한 줄 요약(Summary) |
| Bloom's Taxonomy | 이해도 체크 & 셀프 테스트 | 기억→이해→적용→분석→평가 단계별 질문 |
| Feynman Technique | "비유로 이해하기" | 설명할 수 없으면 이해한 게 아니다 |
| Progressive Sum. L5 | "Book on a Page" | 전체를 한 페이지로 압축 |
| Zettelkasten | 용어 사전 & 내 생각 | 볼트 내부 `[[]]` 링크로 지식 네트워크 |

## 전체 구조

1. **Book on a Page** — Progressive Summarization Layer 5
2. **읽기 전 질문** — SQ3R의 Question
3. **Part 1~N** — 책의 실제 Part/Chapter 구조를 따라감. 각 파트 내부는 Cornell 구조:
   - 핵심 질문 (Cornell Cue Column)
   - 문제 상황 → 핵심 개념 → 코드 & 실전 적용 → 흔한 실수 → 비유로 이해하기 (Feynman)
   - 한 줄 요약 (Cornell Summary)
   - 이해도 체크 (Bloom 단계별)
4. **종합 정리** — 큰 그림 + 플로우차트
5. **용어 사전** — Zettelkasten: 볼트 내부 링크
6. **셀프 테스트** — SQ3R의 Recite + Bloom 인지 단계별 배치
7. **복습 로그** — SQ3R의 Review + 간격 반복
8. **보충자료**
9. **내 생각 & 연결** — Zettelkasten: 기존 지식과 연결

## Part 내부 작성 상세 가이드 (Cornell 구조)

### 핵심 질문 (Cornell Cue Column, 3~5개)
- 이 파트를 읽고 답할 수 있어야 하는 기술적 질문들
- "왜 이렇게 설계했는가?", "트레이드오프는?", "대안은?" 형태
- 나중에 노트를 가리고 이 질문만 보며 인출 연습용으로 사용

### 문제 상황 (3~5문장)
- "~를 구현할 때, ~한 상황이 발생하면 ~가 문제가 된다"
- 기존 방식 vs 새 방식 대비 포함
- 개발자가 공감할 수 있는 구체적 장면 묘사

### 핵심 개념 (가장 긴 섹션, 5~10문장)
- "무엇인가 → 어떻게 동작하는가 → 왜 그렇게 설계되었는가" 흐름
- 비교표 활용:

```markdown
| 구분 | A 방식 | B 방식 |
|------|-------|-------|
| 핵심 원리 | | |
| 장점 | | |
| 단점 | | |
| 적합한 상황 | | |
```

- 수치/벤치마크 반드시 보존
- 개념 간 연결 문장: "앞서 설명한 ~와 결합하여 ~를 가능하게 한다"

### 비유로 이해하기 (Feynman Technique, 1~2문장)
- 비전공자에게 설명하듯 일상의 비유
- "이것은 마치 도서관의 색인 시스템처럼..." 수준
- 핵심: 쉽게 설명할 수 없다면 이해한 게 아님

### 코드 & 실전 적용
- 코드 블록 내 `// 주석`으로 각 줄의 존재 이유 설명
- 코드 아래에 산문으로 실행 흐름 해설
- 실무 적용 시 주의사항 (환경 설정, 의존성, 버전 등)
- 책에서 강조한 "주의하세요" 부분은 빠짐없이 포함

### 흔한 실수 (callout)
```markdown
> [!warning] 흔한 실수 & 삽질 포인트
> "~하면 ~에러가 발생한다" 또는 "~로 착각하기 쉽지만 실제로는 ~이다"
```

### 한 줄 요약 (Cornell Summary, 1문장)
- 이 파트 전체의 핵심을 한 문장으로 압축
- 복습 시 이 한 문장만 보고 전체 내용을 인출하는 앵커 역할

### 이해도 체크 (Bloom's Taxonomy 4단계)
```markdown
### Part N 이해도 체크

- [ ] **기억**: 이 파트의 핵심 개념과 정의를 떠올릴 수 있다
- [ ] **이해**: 작동 원리를 비유로 설명할 수 있다
- [ ] **적용**: 코드의 각 단계가 무엇을 하는지 따라갈 수 있다
- [ ] **분석**: A방식과 B방식의 트레이드오프를 구분할 수 있다
```

### 파트 간 연결
Part 2 이후는 반드시 이전 파트와 연결로 시작:
"앞서 ~를 이해했다면, 다음 질문은 자연스럽게 '~는 어떻게 하는가?'이다"

## 분량 목표

본문 8,000~15,000자. 챕터당 최소 2,000자.
