# Passive Voice (수동태) - 복습 워크북

---

## ⚡ 핵심 공식

### 기본 구조
```
주어 + be동사 + 과거분사(V3) + (by 행위자)
```

### 시제별 be동사 형태
| 시제 | 형태 | 예시 |
|------|------|------|
| 현재 | am/is/are + PP | is written |
| 과거 | was/were + PP | was written |
| 미래 | will be + PP | will be written |
| 현재진행 | am/is/are being + PP | is being written |
| 과거진행 | was/were being + PP | was being written |
| 현재완료 | have/has been + PP | has been written |
| 과거완료 | had been + PP | had been written |
| 미래완료 | will have been + PP | will have been written |
| 조동사 | 조동사 + be + PP | must be written |
| to 부정사 | to be + PP | to be written |

### 신호 단어
- **수동태 사용 신호**: by, was/were, has/have been, is being, must be, should be
- **시제 신호**: yesterday (과거), every day (현재), tomorrow (미래), already/just (완료)

---

## ⚠️ 한국인 오류 TOP 5

### 1. 자동사를 수동태로 만드는 실수
❌ The accident **was happened** yesterday.
✅ The accident **happened** yesterday.

> 💡 **자동사 암기**: happen, occur, appear, arrive, fall, vanish, die, exist

### 2. be동사 누락
❌ The letter **written** by her.
✅ The letter **was written** by her.

### 3. 과거분사 대신 과거형 사용
❌ The window was **broke**.
✅ The window was **broken**.

### 4. 완료 수동태에서 been 누락
❌ The report has **submitted**.
✅ The report has **been submitted**.

### 5. 조동사 수동태에서 be 누락
❌ The task must **completed**.
✅ The task must **be completed**.

## 🔑 핵심 예문 12선

### 초급 (4개)
1. **The letter is written every day.**
   - 현재 시제 수동태 (is + PP)

2. **The window was broken yesterday.**
   - 과거 시제 수동태 (was + PP)

3. **Your order is being prepared.**
   - 현재진행 수동태 (is being + PP)

4. **The message will be sent tomorrow.**
   - 미래 시제 수동태 (will be + PP)

### 중급 (4개)
5. **The report has been submitted.**
   - 현재완료 수동태 (has been + PP)

6. **The project had been completed before the deadline.**
   - 과거완료 수동태 (had been + PP)

7. **All applications must be received by Friday.**
   - 조동사 수동태 (must be + PP)

8. **The issue is being investigated by the team.**
   - 현재진행 수동태 + by 행위자

### 고급 (4개)
9. **The manuscript is believed to have been written in the 15th century.**
   - 완료 부정사 수동태 (to have been + PP)

10. **Had the warning been taken seriously, the disaster could have been prevented.**
    - 가정법 과거완료 수동태 도치 (Had + S + been + PP)

11. **It is essential that all evidence be preserved.**
    - 가정법 현재 수동태 (that + S + be + PP)

12. **Having been approved by the committee, the proposal was implemented.**
    - 완료 분사구문 수동태 (Having been + PP)

## ⚡ 빠른 자가 테스트 (10문제)

### 빈칸 채우기 (3문제)

1. The meeting _______ (postpone) until next week.
> [!success]- 정답
> **has been postponed**
> 현재완료 수동태

2. All passengers _______ (require) to wear seatbelts.
> [!success]- 정답
> **are required**
> 현재 시제 수동태

3. The new policy _______ (implement) by the end of this month.
> [!success]- 정답
> **will be implemented** 또는 **will have been implemented**
> 미래 시제 수동태

### 오류 교정 (2문제)

4. ❌ The problem was occured because of the bug.
> [!success]- 정답
> ✅ The problem **occurred** because of the bug.
> (occur는 자동사 - 수동태 불가)

5. ❌ The email has sent to all employees.
> [!success]- 정답
> ✅ The email has **been sent** to all employees.
> (현재완료 수동태: has/have been + PP)

### Fill the Gap (3문제)

6. **그 제안은 위원회에 의해 거절되었지만, 수정 후 다시 제출될 수 있다.**
> [!success]- 정답
> The proposal **was rejected** by the committee, but it **can be resubmitted** after revision.

7. **직원들은 새 시스템 사용법에 대해 교육받았다.**
> [!success]- 정답
> Employees **have been trained** on how to use the new system.

8. **이 문서는 마감 전에 검토되어야 한다.**
> [!success]- 정답
> This document **must be reviewed** before the deadline.

### 어순 배열 (2문제)

9. [ been / the / has / project / completed / successfully ]
> [!success]- 정답
> **The project has been completed successfully.**

10. [ be / should / before / the / checked / document / submitted / it / is ]
> [!success]- 정답
> **The document should be checked before it is submitted.**

## ✅ 마스터 체크리스트

### 기본 개념
- [ ] 수동태의 기본 구조(S + be + PP)를 설명할 수 있다
- [ ] 능동태를 수동태로 바꿀 수 있다
- [ ] 수동태를 사용하는 4가지 상황을 알고 있다

### 시제별 수동태
- [ ] 현재/과거/미래 단순 수동태를 만들 수 있다
- [ ] 현재/과거 진행 수동태를 만들 수 있다
- [ ] 현재/과거/미래 완료 수동태를 만들 수 있다
- [ ] 조동사 + 수동태를 만들 수 있다 (can/must/should be + PP)

### 고급 구조
- [ ] to 부정사 수동태를 사용할 수 있다 (to be + PP)
- [ ] 완료 부정사 수동태를 이해한다 (to have been + PP)
- [ ] 분사구문 수동태를 이해한다 (Having been + PP)
- [ ] 가정법 + 수동태를 이해한다 (Had + S + been + PP)

### by 생략
- [ ] by + 행위자를 생략해야 하는 4가지 경우를 안다
- [ ] by + 행위자를 반드시 써야 하는 경우를 안다
- [ ] by 외의 전치사(with, in, at)를 구분할 수 있다

### 오류 회피
- [ ] 자동사와 타동사를 구분할 수 있다
- [ ] 자동사를 수동태로 쓰지 않는다 (happen, occur, appear 등)
- [ ] 과거형과 과거분사를 구분한다 (broke vs broken)
- [ ] be동사와 been을 빠뜨리지 않는다

### 실전 활용
- [ ] 격식체 글쓰기에서 수동태를 적절히 사용할 수 있다
- [ ] get 수동태를 구어체에서 자연스럽게 쓸 수 있다
- [ ] "It is said that..." 구문을 사용할 수 있다
- [ ] have/get something done을 사용할 수 있다

## 📚 빠른 참조

### 자동사 (수동태 불가)
```
happen, occur, appear, arrive, fall, vanish, die, exist, emerge, rise
```

### 조동사 수동태 공식
```
can/could/may/might/must/should/ought to + be + PP
```

### 완료형 수동태 공식
```
have/has/had + been + PP
will have been + PP
```

### get 수동태 (구어체)
```
get + PP = be + PP (비격식)
I got fired. = I was fired.
She got promoted. = She was promoted.
```

### It is said that... 구문
```
It is said/believed/thought/reported that + S + V
= S + is said/believed/thought/reported + to V
```
