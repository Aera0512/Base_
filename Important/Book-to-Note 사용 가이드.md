# Book-to-Note 사용 가이드

> 책 제목을 입력하면 웹 검색으로 핵심 내용을 수집하여 구조화된 학습 노트를 자동 생성하는 에이전트 스킬
> **버전**: 2.0 | **최종 수정**: 2026-03-04

---

## 한 줄 요약

책 제목(+저자)을 주면, 웹 검색으로 핵심 내용을 다각도로 수집하고 AI가 분석하여 **원서 구조를 따르는 학습 노트**를 옵시디언에 자동 저장한다.

---

## 사전 준비

### 필수 환경

| 항목 | 상태 | 설명 |
|------|:----:|------|
| Obsidian MCP | ✅ 연결됨 | 볼트 읽기/쓰기/검색 |
| Claude 웹 검색 | ✅ 내장 | 도서 정보 수집 + 보충자료 |

YT-to-Note와 달리 별도 MCP 설치가 필요 없다. 웹 검색만으로 동작한다.

---

## 기본 사용법

### 1. 가장 간단한 방법

Claude Code 또는 Cowork에서 이렇게 말하면 된다:

```
아토믹 해빗 책 노트 만들어줘
```

이것만으로 전체 파이프라인이 실행된다:
1. 웹 검색으로 도서 메타데이터 수집
2. 장르 자동 판별 (tech / knowledge / selfhelp)
3. 핵심 내용 다각도 검색 (최소 5회)
4. 서브에이전트로 구조화된 분석
5. 노트 생성 (원서 구조 반영)
6. 보충자료 검색
7. 내부 링크 생성
8. `Book-to-Note/`에 자동 저장

### 2. 저자를 함께 지정할 때

동명의 책이 여러 권 있을 때 유용하다:

```
제임스 클리어의 아토믹 해빗 노트 정리해줘
```

### 3. 장르를 직접 지정할 때

```
클린 코드 tech 노트로 만들어줘
```

```
사피엔스 knowledge 노트로 정리해줘
```

### 4. 독서일을 지정할 때

```
레버리지 책 2026-02-20에 읽었는데 노트 만들어줘
```

기본값은 오늘 날짜.

## 적용된 학습 프레임워크 (6가지)

이 스킬의 노트 구조는 학술 연구와 PKM 커뮤니티에서 검증된 방법론을 조합하여 설계되었다.

| 프레임워크 | 출처 | 노트에서의 역할 |
|-----------|------|---------------|
| **SQ3R** | 학술 (1946) | 전체 흐름: Survey→Question→Read→Recite→Review |
| **Cornell 5R** | 학술 (1950s) | 각 Part 내부: 핵심 질문 + 내용 + 한 줄 요약 |
| **Bloom's Taxonomy** | 학술 (1956) | 이해도 체크 & 셀프 테스트: 기억→이해→적용→분석→평가 |
| **Feynman Technique** | 실전 | "비유로 이해하기": 쉽게 설명 못하면 이해한 게 아님 |
| **Progressive Sum.** | PKM (Forte) | "Book on a Page": 전체를 한 페이지로 압축 |
| **Zettelkasten** | PKM (Luhmann) | 용어 사전 & 내 생각: 볼트 내부 링크로 지식 네트워크 |

## 지원하는 장르와 특징

### knowledge (지식/교양)

**적합한 책**: 과학, 역사, 경제, 심리학, 철학, 사회, 교양 논픽션

**노트 구조**: 배경 → 저자의 주장과 근거 → 비유 → 한 줄 요약 → 이해도 체크

**특징**:
- 연구/데이터 구체적 보존 (연구자명, N수, 수치)
- 종합 정리에 **비판적 시각** 포함 (전제 검토, 근거 한계, 반대 입장)
- 근거 강도 분석 (일화 vs 통제실험 vs 메타분석)

### tech (기술/개발)

**적합한 책**: 프로그래밍, 아키텍처, 시스템 설계, AI/ML, 개발 방법론

**노트 구조**: 문제 상황 → 핵심 개념 → 비교표 → 코드 & 실전 → 흔한 실수 → 비유 → 한 줄 요약 → 이해도 체크

**특징**:
- 코드 블록 + 주석 해설
- 기술 비교표 (A 방식 vs B 방식)
- `> [!warning]` 흔한 실수 callout
- 공식문서/GitHub 링크 자동 수집

### selfhelp (자기계발/습관)

**적합한 책**: 습관, 생산성, 마인드셋, 리더십, 커뮤니케이션, 커리어

**노트 구조**: 왜 이게 중요한가 → 핵심 원칙 → 프레임워크 & 실천 가이드 → 흔한 오해 → 비유 → 한 줄 요약 → 이해도 체크

**특징**:
- `> [!tip]` 프레임워크 단계별 정리
- `> [!example]` 즉시 실천 → 이번 주 → 30일 챌린지
- 종합 정리에 **90일 실천 로드맵** 포함
- **실천적 시각** (생존자 편향, 이상 vs 현실)

## 생성되는 노트 상세

### 파일 위치와 이름

```
Book-to-Note/Book-{genre}-{YYMMDD}-{제목축약}.md
```

예시:
- `Book-to-Note/Book-knowledge-260304-사피엔스-유발하라리.md`
- `Book-to-Note/Book-tech-260228-클린코드-로버트마틴.md`
- `Book-to-Note/Book-selfhelp-260301-아토믹해빗-제임스클리어.md`

### 노트 전체 구조

| 섹션 | 프레임워크 | 설명 |
|------|-----------|------|
| **Book on a Page** | Progressive Sum. L5 | 한 줄 핵심 + 개요 + 마인드맵 + 암기 포인트 |
| **읽기 전 질문** | SQ3R: Question | 책을 통해 답하고 싶은 5가지 질문 |
| **Part 1~N** | Cornell + Feynman + Bloom | 원서 구조를 따르는 본문 (아래 상세) |
| **종합 정리** | — | 큰 그림 + 비판적/실천적 시각 + 플로우차트 |
| **용어 사전** | Zettelkasten | 핵심 용어 + 정의 + 맥락 + `[[내부 링크]]` |
| **셀프 테스트** | SQ3R: Recite + Bloom | 인지 단계별 인출 연습 (기억→평가) |
| **복습 로그** | SQ3R: Review | 간격 반복 트래킹 (1일/7일/30일) + 기억률 |
| **보충자료** | — | 웹 검색으로 수집한 참고 자료 + 노트 보완 포인트 |
| **내 생각 & 연결** | Zettelkasten | 인사이트 + 적용 계획 + 볼트 내 연결 |

### Part 내부 구조 (Cornell 기반)

각 Part는 원서의 실제 Part/Chapter 구조를 따르며, 내부는 Cornell Notes 형식이다:

```
Part N. {원서 제목} 🟢/🟡/🔴
├── 핵심 질문 (Cornell Cue Column) ← 인출 연습 앵커
├── 배경 / 문제 상황
├── 핵심 내용 (주장+근거 / 개념+코드 / 원칙+프레임워크)
├── 비유로 이해하기 (Feynman)
├── 한 줄 요약 (Cornell Summary)
└── 이해도 체크 (Bloom 4단계)
    ├── 기억: 떠올릴 수 있는가
    ├── 이해: 설명할 수 있는가
    ├── 적용: 다른 상황에 대입할 수 있는가
    └── 분석: 강점/약점을 구분할 수 있는가
```

### 프론트매터

```yaml
type: book-note
genre: tech | knowledge | selfhelp
source: "책 제목"
author: "저자명"
year: 2024
date_read: 2026-03-04
date_created: 2026-03-04
tags: [book-note, 장르, 주제태그들]
review: [null, null, null]     # 복습 기록
confidence: null               # 학습 후 자기 평가 (1~5)
status: processed
version: "2.0"
```

## 학습 워크플로

### 노트 생성 직후

1. **Book on a Page**로 전체 구조 파악
2. **마인드맵**으로 핵심 관계 시각화
3. **암기 포인트** ★★★ 항목 먼저 읽기
4. **읽기 전 질문** 확인 — 학습 목표 설정

### Part별 학습

1. **핵심 질문** 먼저 읽기 — "이걸 답할 수 있어야 한다"
2. 본문 정독 (배경 → 주장/개념 → 비유)
3. **한 줄 요약** 확인 — 내가 이해한 것과 일치하는가
4. **이해도 체크** 체크박스 점검 (Bloom 단계별)
5. 체크 안 되는 항목 → 해당 부분 재학습

### 학습 마무리

1. **종합 정리** 읽고 큰 그림 확인
2. **셀프 테스트** — 노트 가리고 답해보기 (Bloom 단계별)
3. **내 생각 & 연결** 직접 작성 (가장 중요!)
4. `confidence` 프론트매터에 자기 평가 기록 (1~5)

### 간격 복습

| 복습 | 시점 | 방법 |
|------|------|------|
| 1차 | +1일 | 핵심 질문 + 한 줄 요약만 보고 인출 연습 |
| 2차 | +7일 | 셀프 테스트 + 이해도 체크 재점검 |
| 3차 | +30일 | 셀프 테스트만, 틀린 부분 Part 재학습 |

복습 완료 시 **복습 로그** 테이블에 완료일과 기억률(/10) 기록.

## YT-to-Note와의 차이

| 항목 | YT-to-Note | Book-to-Note |
|------|-----------|-------------|
| **입력** | YouTube URL | 책 제목 (+저자) |
| **소스** | 영상 자막 추출 | 웹 검색 다각도 수집 |
| **필수 MCP** | YouTube Transcript MCP | 없음 (웹 검색만) |
| **장르** | tech / knowledge / english | tech / knowledge / selfhelp |
| **구조** | 임의 챕터 분절 | 원서 Part/Chapter 구조 반영 |
| **프레임워크** | Feynman + 간격 반복 | SQ3R + Cornell + Bloom + Feynman + Prog.Sum + Zettelkasten |
| **영상 기능** | iframe 구간 재생 | 없음 |
| **고유 기능** | 자막 기반 정밀 분석 | 읽기 전 질문, Cornell Cue, 복습 로그 |
| **한계** | 자막 없으면 불가 | 웹 정보가 부족한 비주류 책은 품질 저하 |

## 고급 사용법

### 노트 품질 높이는 팁

1. **저자명을 함께 입력**하면 동명 이서 혼동 방지
2. **장르를 직접 지정**하면 판별 오류 방지
3. **"내 생각 & 연결"은 반드시 직접 작성** — Generation Effect로 학습 효과 극대화
4. **기존 노트가 많을수록 내부 링크 품질 향상** — 지식 네트워크 효과
5. **읽기 전 질문을 직접 수정**하면 학습 목표가 명확해짐

### 한계와 주의사항

| 상황 | 동작 |
|------|------|
| 웹 검색 결과가 부족한 책 | 알림 후 사용자에게 추가 정보 요청 |
| 동명의 다른 책 | 저자/출판사로 구분, 사용자에게 확인 |
| 원문을 직접 읽지 않음 | 웹 검색 기반이므로 원문의 미묘한 뉘앙스 누락 가능 |
| 매우 최신 출간 책 | 웹에 정보가 적어 품질 저하 가능 |
| 동일 책 재처리 | 덮어쓰기 여부 확인 |
