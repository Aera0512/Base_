## 코드 규칙

- 파일명: [예: kebab-case]
- 에러 처리: try-catch 필수, 에러 메시지에 맥락 포함
- 로깅: [예: console.log OK / winston 사용 / 없음]

​```
[주요 디렉토리와 역할]
​```

## 작업 방식 (필수 준수)

### 계획 먼저, 코드는 나중에
- 3파일 이상 수정이 필요한 작업: 반드시 Plan Mode로 계획 먼저 세우고, 승인 후 구현
- 1~2파일 수정: 바로 구현 가능하되, 접근 방식을 한 문장으로 먼저 설명
- 아키텍처 변경: plan.md를 작성하고 코드를 작성하지 않음

### 테스트 우선
- 구현 전에 테스트 케이스를 먼저 설계하고 작성
- 테스트가 실패하는 것을 확인한 후 구현 시작
- "통과하지만 아무것도 검증하지 않는" 약한 테스트 금지

### 태스크 단위 작업
- 한 번에 하나의 태스크만 집중
- 태스크 범위를 벗어나는 수정을 발견하면 보고하고 별도 태스크로 분리
- 완료 후 관련 파일만 포함하여 커밋

### 변경 영향 분석
- 수정 전에 해당 코드를 참조하는 다른 파일을 먼저 확인
- 변경이 3개 이상의 후속 작업에 영향을 줄 경우 반드시 알림
