## 6-1. 노트 저장 로직

### 저장 경로 규칙

```
볼트 루트/f. CMDS/20. Literature Notes/
  └── YT-{genre}-{YYMMDD}-{제목축약}.md
```

### 파일명 생성 규칙

| 요소 | 규칙 | 예시 |
|------|------|------|
| `genre` | `tech`, `knowledge`, `english` 중 하나 | `tech` |
| `YYMMDD` | 시청일 (6자리) | `260304` |
| `제목축약` | 영상 제목에서 핵심 키워드 2~4개, 공백은 `-`로 | `React-Server-Components` |

파일명 예시:
- `YT-tech-260304-React-Server-Components.md`
- `YT-knowledge-260304-도파민과-습관형성.md`
- `YT-english-260304-가정법-과거완료.md`

### 파일명 생성 프롬프트

```
다음 영상 정보로 파일명을 생성하세요.

규칙:
1. 형식: YT-{genre}-{YYMMDD}-{제목축약}
2. 제목축약: 핵심 키워드 2~4개를 하이픈으로 연결
3. 한글/영어 모두 허용, 특수문자 제거
4. 30자 이내

영상 제목: {{title}}
장르: {{genre}}
시청일: {{date}}

출력: 파일명만 (확장자 제외)
```

### Obsidian MCP 저장 호출

```
도구: mcp__obsidian__write_note
파라미터:
  path: "f. CMDS/20. Literature Notes/{{파일명}}.md"
  content: {{생성된 노트 본문}}
  frontmatter: {{자동 생성된 프론트매터 객체}}
  mode: "overwrite"
```

### 중복 파일 체크

저장 전에 동일 파일명 존재 여부 확인:

```
도구: mcp__obsidian__get_notes_info
파라미터:
  paths: ["f. CMDS/20. Literature Notes/{{파일명}}.md"]
```

- 파일이 존재하면 → 사용자에게 확인: "동일한 파일명이 이미 존재합니다. 덮어쓸까요?"
- 파일이 없으면 → 바로 저장

## 6-2. 프론트매터 자동 생성

### 프론트매터 스키마

```yaml
---
type: yt-note
genre: tech | knowledge | english
source: "[영상 제목](YouTube URL)"
channel: "채널명"
video_id: "VIDEO_ID"
date_watched: YYYY-MM-DD
date_created: YYYY-MM-DD
subtitle_lang: ko | en
tags:
  - yt-note
  - {장르 태그}
  - {주제 태그 1}
  - {주제 태그 2}
  - {주제 태그 3}
review:
  - null  # 1차 복습 (+1일)
  - null  # 2차 복습 (+7일)
  - null  # 3차 복습 (+30일)
confidence: null  # 학습 후 자기 평가 (1~5)
status: processed
version: "7.0"
---
```

### 태그 자동 생성 로직

```
기본 태그:
- yt-note (고정)
- {genre} (tech/knowledge/english)

주제 태그 생성 프롬프트:
"다음 노트의 핵심 주제를 태그 3~5개로 요약하세요.
규칙: 소문자, 하이픈 허용, 기존 볼트 태그와 일관성 유지
기존 볼트에서 자주 쓰이는 태그: [볼트 태그 목록]
출력: 태그 배열만"
```

### 기존 태그 참조

볼트 내 기존 태그를 검색하여 일관성을 유지:

```
도구: mcp__obsidian__search_notes
파라미터:
  query: "tags"
  searchFrontmatter: true
  limit: 20
```

## 6-3. 내부 링크 생성 로직

### 링크 생성 전략

내부 링크 `[[]]`를 세 가지 위치에 생성한다:

**1. 용어 사전 → 기존 노트 링크**

각 용어에 대해 볼트 내 관련 노트를 검색:

```
도구: mcp__obsidian__search_notes
파라미터:
  query: "{{용어}}"
  limit: 3
```

- 관련 노트가 발견되면: `{{용어}} — [[관련 노트명]]`
- 없으면: 링크 없이 용어만 기록

**2. "내 생각 & 연결" 섹션 → 관련 노트 링크**

노트의 핵심 주제로 볼트를 검색하여 관련 노트를 찾음:

```
도구: mcp__obsidian__search_notes
파라미터:
  query: "{{핵심 주제 키워드}}"
  limit: 5
```

- 관련도 높은 노트 2~3개를 `[[노트명]]` 형태로 삽입
- 각 링크에 "어떤 점에서 연결되는지" 설명 추가

**3. 본문 내 자연스러운 링크**

본문 작성 시 기존 볼트에 있는 개념/용어가 등장하면 `[[]]`로 감싸기:

```
검색 대상: 노트의 핵심 용어 목록
검색 도구: mcp__obsidian__search_notes

각 용어에 대해:
  - 볼트에 해당 노트가 있으면 → [[용어]] 또는 [[노트명|표시 텍스트]]
  - 없으면 → 일반 텍스트 유지
```

### 링크 품질 기준

- 무관한 링크를 생성하지 않는다 (정확도 > 관련성)
- 한 노트당 내부 링크 최소 2개, 최대 10개
- `[[]]` 내부에는 볼트에 실제 존재하는 노트명만 사용
- 존재하지 않는 노트에 대한 링크는 만들지 않는다 (빈 링크 방지)

### 링크 생성 프롬프트

```
다음 노트에 옵시디언 내부 링크를 추가하세요.

볼트 검색 결과:
{{검색으로 찾은 관련 노트 목록}}

규칙:
1. 실제 존재하는 노트만 [[]] 링크 사용
2. 용어 사전의 "맥락" 열에 관련 노트 링크 추가
3. "내 생각 & 연결" 섹션에 관련 노트 2~3개 연결
4. 각 연결에 "어떤 점에서 연결되는지" 한 줄 설명 추가
5. 본문에서 기존 노트의 주제가 언급되면 자연스럽게 링크
```

## 6-4. 에러 핸들링

### 에러 시나리오 및 대응

| 에러 | 원인 | 대응 |
|------|------|------|
| 경로 없음 | `f. CMDS/20. Literature Notes/` 폴더 미존재 | 사용자에게 경로 확인 요청 |
| 중복 파일명 | 동일 영상 재처리 | 사용자에게 덮어쓰기 확인 |
| MCP 연결 실패 | Obsidian MCP 서버 비활성 | "Obsidian이 실행 중인지 확인해주세요" 안내 |
| 프론트매터 파싱 에러 | YAML 형식 오류 | 프론트매터를 JSON으로 변환하여 재시도 |
| 노트 크기 초과 | 매우 긴 영상의 노트 | 챕터 수를 줄이거나 요약 밀도 조절 |
| 내부 링크 검색 실패 | 볼트 검색 MCP 오류 | 내부 링크 없이 노트 저장 후 수동 보완 안내 |

### 저장 후 검증

노트 저장 후 자동 검증:

```
도구: mcp__obsidian__read_note
파라미터:
  path: "f. CMDS/20. Literature Notes/{{파일명}}.md"

검증 항목:
1. 파일이 정상 저장되었는가 (read 성공)
2. 프론트매터가 올바른가 (type, genre, source 필드 존재)
3. 본문 구조가 온전한가 (## 개요, ## Chapter 존재)
4. 내부 링크가 1개 이상 포함되었는가
```

## 6-5. 전체 저장 워크플로

```
[완성된 노트 수신]
    │
    ├─ 1. 파일명 생성
    │     └─ YT-{genre}-{YYMMDD}-{제목축약}
    │
    ├─ 2. 중복 체크
    │     ├─ 존재 → 사용자 확인
    │     └─ 미존재 → 계속
    │
    ├─ 3. 프론트매터 조립
    │     └─ 스키마에 따라 자동 생성
    │
    ├─ 4. 내부 링크 생성
    │     ├─ 핵심 용어 → 볼트 검색 → [[링크]] 삽입
    │     ├─ 관련 노트 → "내 생각 & 연결" 에 삽입
    │     └─ 본문 내 자연 링크
    │
    ├─ 5. Obsidian MCP로 저장
    │     └─ write_note(path, content, frontmatter)
    │
    ├─ 6. 저장 검증
    │     └─ read_note로 확인
    │
    └─ 7. 사용자에게 결과 보고
          ├─ "노트가 저장되었습니다: [[YT-tech-260304-React-RSC]]"
          ├─ 연결된 내부 링크 목록
          └─ 다음 단계 안내 (복습 일정, Note Linker 실행 등)
```

## 검증 기준

- [ ] 지정 경로에 노트가 정상 저장됨
- [ ] 프론트매터가 스키마대로 생성됨
- [ ] 파일명이 규칙을 따름
- [ ] 관련 기존 노트가 있을 때 최소 1개 내부 링크 생성
- [ ] 기존 노트가 없을 때 빈 링크 `[[]]`가 생성되지 않음
- [ ] 중복 파일명 시 사용자 확인 프로세스 동작
- [ ] 저장 후 검증에서 구조 온전성 확인
