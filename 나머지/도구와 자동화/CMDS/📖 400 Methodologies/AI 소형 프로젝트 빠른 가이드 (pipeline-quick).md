# AI 소형 프로젝트 빠른 가이드

> **대상**: 1~3일 규모, 혼자 작업, 학습 또는 단일 기능 구현
>
> **도구**: Claude (기획) + Claude Code (구현)
>
> **원칙**: 작아도 계획은 있어야 한다 — 단, 5분이면 충분하다
>
> **최종 수정**: 2026-03-04 | 버전: 1.0

---

## 이 가이드를 쓸 때

아래 질문에 **모두 "아니오"**라면 이 가이드로 충분하다:

- 외부 API/서비스가 3개 이상인가?
- 수정할 파일이 10개 이상 예상되는가?
- 여러 사람이 협업하는가?
- DB 스키마 설계가 필요한가?

하나라도 "예"라면 → **[[나머지/도구와 자동화/CMDS/📖 400 Methodologies/AI 프로젝트 기획-실행 파이프라인 (pipeline-full)]]** 사용을 권장한다.

**적합한 프로젝트 예시**: 단일 n8n 워크플로우, 간단한 스크립트, CLI 도구, 소규모 API 연동, 학습 목적 프로토타입

---

## 전체 흐름

```
아이디어 (5분) → 미니 PRD (10분) → Plan → 구현 → 검증
```

Task Master 불필요. CLAUDE.md는 기존 것 재활용 또는 간단히 작성.

---

## Step 1: 아이디어 정리 (5분)

Claude에게 자연어로 설명하고, 핵심만 확정한다.

### 대화 템플릿

```
나는 [만들고 싶은 것]을 만들고 싶어.

다음을 빠르게 정리해줘:
1. 이 프로젝트에서 꼭 필요한 핵심 기능 (3개 이내)
2. 사용할 기술 스택 제안
3. 예상 소요 시간
4. 시작하기 전에 확인해야 할 것 (API 키, 계정 등)
```

### 확정할 것 (이것만 정하면 된다)

| 항목 | 질문 | 예시 |
|------|------|------|
| **What** | 정확히 뭘 만드는가? | RSS → Slack 요약 봇 |
| **How** | 어떤 기술로? | n8n + Claude API |
| **Done** | 완성 기준은? | RSS 읽고 Slack에 요약 전송 성공 |

---

## Step 2: 미니 PRD (10분)

정식 PRD가 아니다. 입력/출력/완료 기준만 적는다.

### 미니 PRD 템플릿

```markdown
# [프로젝트명] 미니 PRD

## 목적
[한 문장: 이 프로젝트가 해결하는 문제]

## 기능 정의

### 기능 1: [이름]
- 입력: [무엇을 받는가]
- 처리: [무엇을 하는가]
- 출력: [무엇을 내보내는가]
- 완료 기준: [어떻게 되면 성공인가]

### 기능 2: [이름] (필요 시)
- 입력:
- 처리:
- 출력:
- 완료 기준:

## 기술 제약
- [사용할 기술/플랫폼]
- [비용 한도, 있다면]

## 안 하는 것
- [이번에 안 하는 것 명시 — 스코프 크리프 방지]
```

### 예시: RSS → Slack 요약 봇

```markdown
# RSS-Slack 요약 봇 미니 PRD

## 목적
기술 블로그 RSS를 자동으로 읽고 Slack에 한국어 요약을 보낸다.

## 기능 정의

### 기능 1: RSS 수집
- 입력: RSS 피드 URL 3개
- 처리: 최근 24시간 내 새 글 필터링
- 출력: 글 제목 + URL + 본문
- 완료 기준: 새 글이 있을 때 정확히 수집됨

### 기능 2: AI 요약 + Slack 전송
- 입력: 수집된 글 본문
- 처리: Claude API로 3줄 한국어 요약 생성
- 출력: Slack 채널에 요약 메시지 전송
- 완료 기준: 요약이 원문 핵심을 담고 있음, Slack에 정상 전송

## 기술 제약
- n8n (self-hosted) + Claude API
- 월 비용 $5 이내

## 안 하는 것
- 요약 품질 평가 자동화 (수동 확인)
- 다국어 지원
```

**팁**: Claude에게 "이 미니 PRD에서 빠진 게 있어?"라고 한 번만 물어보면 엣지 케이스를 잡을 수 있다.

---

## Step 3: 구현

### 3-1. CLAUDE.md (있으면 재활용, 없으면 간단히)

이미 CLAUDE.md가 있는 프로젝트라면 그대로 쓴다. 새 프로젝트라면:

```bash
# Claude가 자동 생성 (코드베이스가 있을 때)
claude /init

# 또는 최소한으로 직접 작성
```

```markdown
# 프로젝트: [이름]
## 기술 스택
- [사용 기술 나열]
## 절대 하지 말 것
- [있다면]
```

소형 프로젝트에서는 CLAUDE.md가 10줄이어도 충분하다. 프로젝트가 끝난 후 배운 것만 추가하면 된다.

CLAUDE.md 템플릿이 필요하면 → **[[나머지/시스템/템플릿/CLAUDE-template]]** 참고

### 3-2. Plan → 구현

**3파일 이상 수정할 때**: 반드시 Plan Mode 사용

```bash
# Plan Mode로 시작
claude --permission-mode plan

# 또는 세션 중에 전환: Shift+Tab 두 번
```

**1~2파일만 수정할 때**: 바로 구현해도 된다. 계획이 한 문장이면 Plan 불필요.

### 실행 패턴

```
1. Plan Mode에서 계획 생성
   "미니 PRD를 읽고 구현 계획을 세워줘. 코드는 아직 작성하지 마."

2. 계획 검토 → 수정 (Ctrl+G로 에디터에서 직접 편집)

3. Normal Mode로 전환 → 구현
   "계획대로 구현해줘."

4. 테스트 / 동작 확인
```

### 3-3. 막혔을 때

| 상황 | 대응 |
|------|------|
| Claude가 같은 실수 반복 | CLAUDE.md에 규칙 추가 + 새 세션 |
| 에러 원인 모를 때 | 에러 메시지 전체 붙여넣기 → "단계별로 분석해줘" |
| 계획대로 안 될 때 | Plan Mode로 돌아가서 대안 탐색 |
| API/라이브러리 정보 부족 | Claude에게 웹 검색 요청 또는 공식 문서 URL 전달 |
| 컨텍스트가 오염된 느낌 | `/clear` 후 미니 PRD + 현재 상태만 새로 전달 |
| 세션이 길어져서 품질 저하 | 50% 시점에서 `/compact`, 심하면 새 세션 시작 |

## Step 4: 검증 & 마무리

### 완료 체크리스트

```
- [ ] 미니 PRD의 모든 완료 기준을 충족하는가?
- [ ] 에러 상황에서 적절히 동작하는가? (API 실패, 잘못된 입력 등)
- [ ] .env에 API 키가 분리되어 있는가? (.gitignore 확인)
- [ ] 다음에 이 코드를 보면 이해할 수 있는가?
```

### 배운 것 기록 (30초)

CLAUDE.md 하단에 한 줄이라도 추가한다:

```markdown
## 배운 교훈
- n8n HTTP Request 노드: timeout을 반드시 명시해야 함
```

이 한 줄이 다음 프로젝트에서 30분을 아껴준다.

### Git 커밋

```bash
git add .
git commit -m "feat: [프로젝트명] 완성

- [핵심 기능 1]
- [핵심 기능 2]"
```

소형 프로젝트는 커밋 1~3개면 충분하다.

## 프로젝트가 커지고 있다면

다음 신호가 보이면 **[[나머지/도구와 자동화/CMDS/📖 400 Methodologies/AI 프로젝트 기획-실행 파이프라인 (pipeline-full)]]**로 전환을 고려한다:

- "이거 하나만 더 추가하면..." 이 3번 이상 반복됨
- 파일이 10개를 넘어감
- 한 세션에서 끝나지 않고 며칠째 이어짐
- 의존성 관리가 머릿속으로 안 됨

**전환 방법**:
1. 현재까지의 미니 PRD를 정식 PRD로 확장
2. Task Master를 설치하고 태스크 분해
3. pipeline-full의 Phase 4부터 따라가기

## 빠른 참조: Claude Code 필수 조작

| 조작 | 설명 |
|------|------|
| `Shift+Tab` x2 | Plan Mode ↔ Normal Mode 전환 |
| `Ctrl+G` | 계획을 에디터에서 직접 편집 |
| `/clear` | 컨텍스트 초기화 |
| `/compact` | 대화 요약 (컨텍스트 절약) |
| `/init` | CLAUDE.md 자동 생성 |
| `Escape` | Claude 실행 중지 |
| `Escape` x2 | 이전 메시지 목록 |
