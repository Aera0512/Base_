## 워크플로우 1: 폰으로 코드 개발

Telegram 채팅만으로 원격 서버나 로컬 머신의 코드를 개발하는 워크플로우입니다.

### 단계별 진행

```
1. /project <경로>          # 작업 디렉토리 설정
2. 자연어로 작업 설명 전송     # "로그인 API에 에러 핸들링 추가해줘"
3. Claude가 파일 읽기/편집     # Read, Write, Edit 도구 사용
4. 스트리밍 출력 확인          # 실시간으로 진행 상황 확인
5. /continue                # 중단 시 이어하기
```

### 실전 예시

```
사용자: /project /home/user/my-app
사용자: src/api/auth.ts에서 로그인 실패 시 적절한 에러 메시지를 반환하도록 수정해줘
Claude: [파일 읽기 → 분석 → 코드 수정 → 테스트 실행]
사용자: /continue   (응답이 길어서 중단된 경우)
```

> [!tip] 복잡한 작업
> 복잡한 작업에는 `/plan` 모드를 사용하면 Claude가 단계별 계획을 세우고 실행합니다.

## 워크플로우 2: 콘텐츠 리서치 및 요약

Reddit과 Medium의 콘텐츠를 수집하고 Claude가 분석/요약하는 워크플로우입니다.

### 단계별 진행

```
1. /reddit <URL>            # Reddit 게시물/스레드 가져오기
2. /medium <URL>            # Medium 유료 기사 읽기
3. Claude에게 분석 요청       # "이 두 자료를 비교 분석해줘"
4. /telegraph               # 긴 결과를 Instant View로 확인
```

### 실전 예시

```
사용자: /reddit https://reddit.com/r/programming/comments/xxx
사용자: /medium https://medium.com/@author/some-article
사용자: 두 자료에서 공통적으로 추천하는 아키텍처 패턴을 정리해줘
Claude: [두 자료 분석 → 비교표 생성 → 요약 제공]
```

> [!info] 연동 상세
> Reddit과 Medium 연동의 상세 설정은 [[나머지/도구와 자동화/CMDS/📖 900 AI Tools/Claudegram/integrations|외부 연동]]을 참고하세요.

## 워크플로우 3: 음성 기반 상호작용

음성 입력과 TTS 출력을 결합한 핸즈프리 워크플로우입니다.

### 단계별 진행

```
1. 음성 메모 전송              # 자동 변환 → Claude 처리
2. /tts                      # TTS 응답 활성화
3. 핸즈프리 루프 시작           # 음성 입력 → 음성 출력 반복
```

### 활용 시나리오

| 시나리오 | 설명 |
|----------|------|
| 이동 중 코딩 | 걸으면서 음성으로 코드 변경 요청 |
| 아이디어 브레인스토밍 | 음성으로 아이디어 나열, Claude가 정리 |
| 문서 리뷰 | 긴 문서를 Claude가 읽어줌 |
| 학습 도우미 | 개념 설명을 음성으로 들으며 학습 |

### 음성 설정

```
/tts nova                   # 에너지 넘치는 음성으로 변경
/tts sage                   # 차분한 음성으로 변경
```

> [!tip] TTS 음성 목록
> 사용 가능한 13가지 음성은 [[나머지/도구와 자동화/CMDS/📖 900 AI Tools/Claudegram/integrations#텍스트 음성 변환 OpenAI TTS|외부 연동]]에서 확인하세요.

## 워크플로우 4: 멀티 세션 프로젝트 관리

여러 프로젝트를 독립적인 세션으로 관리하는 워크플로우입니다.

### 단계별 진행

```
1. /newproject <경로>        # 프로젝트 A 세션 생성
2. (작업 수행)
3. /newproject <다른 경로>    # 프로젝트 B 세션 생성
4. /sessions                # 모든 세션 목록 확인
5. /resume <id>             # 프로젝트 A로 복귀
6. /status                  # 현재 컨텍스트 확인
```

### 세션 관리 명령어

| 명령어 | 용도 |
|--------|------|
| `/newproject` | 격리된 새 워크스페이스 생성 |
| `/sessions` | 활성 세션 목록 보기 |
| `/resume` | 이전 세션으로 전환 |
| `/status` | 현재 세션 정보 확인 |
| `/clear` | 현재 세션 초기화 |

> [!tip] 프로젝트 격리
> 각 세션은 독립적인 컨텍스트를 가지므로 프로젝트 간 간섭 없이 작업할 수 있습니다.

## 워크플로우 5: 자체 편집 (Claudegram이 스스로 코드 수정)

Claudegram이 자기 자신의 코드를 편집하고 재시작하는 워크플로우입니다.

### 단계별 진행

```
1. 프로덕션 모드로 실행        # npm run start (핫 리로드 없음)
2. Claude에게 코드 변경 요청   # "이 기능을 추가/수정해줘"
3. Claude가 소스 파일 편집     # Write/Edit 도구 사용
4. /restartbot               # 봇 재시작으로 변경 적용
5. /continue                 # 세션 복원 후 계속
```

> [!warning] 중요
> 반드시 **프로덕션 모드**(핫 리로드 없음)에서 실행해야 합니다. 개발 모드에서는 파일 변경 시 자동 재시작되어 세션이 유실될 수 있습니다.

### 자체 편집이 유용한 경우

- 새 명령어 추가
- 버그 수정
- 기능 개선
- 설정 변경

> [!info] 개발 모드 차이
> dev vs prod 모드의 차이점은 [[나머지/도구와 자동화/CMDS/📖 900 AI Tools/Claudegram/setup-and-config#개발 모드|설치 및 설정]]에서 확인하세요.

## 팁 및 모범 사례

### 에이전트 모드 활용

| 모드 | 추천 상황 |
|------|-----------|
| `/plan` | 여러 파일을 수정하는 복잡한 작업 |
| `/explore` | 코드베이스 구조 파악이나 질문 |
| `/loop` | 테스트 → 수정 → 재테스트 반복 작업 |

### 모델 전환 전략

```
/model haiku               # 간단한 질문에 빠른 응답
/model sonnet              # 일반 작업 (기본값)
/model opus                # 복잡한 추론 필요 시
```

> [!tip] 비용 최적화
> 간단한 질문은 Haiku, 복잡한 작업은 Opus로 전환하면 비용과 성능의 균형을 맞출 수 있습니다.

### 컨텍스트 관리

- `/context` — 현재 토큰 사용량 확인
- `/clear` — 컨텍스트가 커졌을 때 초기화
- `/continue` — 중단된 작업 이어하기

### 일반 팁

1. **구체적으로 요청하기** — "이 파일을 수정해줘"보다 "src/api/auth.ts의 login 함수에서 에러 핸들링을 추가해줘"가 더 효과적
2. **단계적으로 진행하기** — 큰 작업은 `/plan`으로 계획 후 실행
3. **세션 활용하기** — 관련 작업은 같은 세션에서, 다른 프로젝트는 `/newproject`로 분리
4. **토큰 모니터링** — `/context`로 사용량 확인, 필요 시 `/clear`
