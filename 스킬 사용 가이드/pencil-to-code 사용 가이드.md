# Pencil-to-Code 스킬 사용 가이드

Pencil 디자인(.pen 파일)을 React/Next.js 코드로 변환하는 스킬입니다.

## 빠른 시작

```
/pencil-to-code
```

또는 .pen 파일을 언급하면 자동 트리거:
```
"dashboard.pen을 React 컴포넌트로 변환해줘"
```

---

## 6-PASS 워크플로우

```
┌─────────────────────────────────────────────────────┐
│ PASS 1: 토큰 추출                                    │
│         → design-tokens.json                        │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│ PASS 2: 시맨틱 추론                                  │
│         → semantic-context.json                     │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│ PASS 3: 사용자 상의                                  │
│         ◀─ 여기서 의견 제시 필요                     │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│ PASS 4: 구현 계획 생성                               │
│         ◀─ 여기서 승인 필요                          │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│ PASS 5: 코드 생성                                    │
│         → React/Next.js 컴포넌트                    │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│ PASS 6: 검증                                        │
│         → 검증 리포트                                │
└─────────────────────────────────────────────────────┘
```

---

## 각 PASS 상세 설명

### PASS 1: 디자인 토큰 추출

**목적**: Pencil의 모든 스타일 변수를 코드에서 사용할 수 있는 형태로 추출

**추출 항목**:
- 색상 팔레트 (primary, secondary, background 등)
- 타이포그래피 (폰트, 크기, 굵기)
- 간격 체계 (padding, margin, gap)
- 테두리 반경, 그림자
- 재사용 가능한 컴포넌트 목록

**출력**: `design-tokens.json`

---

### PASS 2: 시맨틱 컨텍스트 추론

**목적**: UI에서 의미와 의도 추출 (단순 시각 정보가 아닌)

**4계층 분석**:
1. **제품 레벨**: 앱의 목적, 타겟 사용자
2. **디자인 시스템 레벨**: 스타일 언어, 톤앤매너
3. **기능 레벨**: 화면의 역할, 정보 구조
4. **컴포넌트 레벨**: 각 요소의 의미, 상태, 인터랙션

**출력**: `semantic-context.json`

---

### PASS 3: 사용자 상의 (중요!)

**목적**: 분석 결과 제시 + 창의적 제안 + 피드백 수렴

**제시되는 내용**:
```markdown
## 📋 분석 요약
- 화면 수, 컴포넌트 수, 토큰 수
- 추론된 목적과 타겟 사용자
- 필요한 데이터 엔티티

## 💡 제안 (선택)
- UX 개선: 스켈레톤 로딩, 에러 상태, 빈 상태
- 기술 개선: React Query, 코드 스플리팅
- 기능 추가: 다크모드, 키보드 내비게이션

## ⚠️ 확인 필요
- 디자인에 없지만 필요한 상태들
- 모호한 요소 명확화
```

**여기서 할 일**:
- 제안 중 원하는 것 선택
- 질문에 답변
- 기술 스택 확인

---

### PASS 4: 구현 계획 생성

**목적**: 승인된 컨텍스트 기반 상세 구현 계획

**계획 내용**:
- 파일 구조 제안
- 컴포넌트 구현 순서 (의존성 고려)
- 상태 관리 구조
- API 레이어 설계
- 상태 커버리지 (loading, error, empty 등)

**출력**: `docs/plans/YYYY-MM-DD-pencil-implementation.md`

**여기서 할 일**: 계획 검토 후 승인

---

### PASS 5: 코드 생성

**목적**: 승인된 계획에 따른 코드 구현

**생성 순서**:
1. 토큰 파일 (CSS variables / tailwind.config.js)
2. 기반 컴포넌트 (Button, Card, Input)
3. 복합 컴포넌트 (MetricCard, Sidebar)
4. 페이지 컴포넌트
5. 상태 관리 / API 레이어

**핵심 규칙**:
- ✅ 모든 스타일 값은 토큰 참조 (하드코딩 금지)
- ✅ 시맨틱 HTML (div soup 금지)
- ✅ 모든 상태 구현 (loading, error, empty)
- ✅ 접근성 포함 (ARIA, 키보드, 색상 대비)

---

### PASS 6: 검증

**목적**: 디자인-구현 일치도 검증

**검증 항목**:
| 항목 | 확인 내용 |
|------|----------|
| 시각적 비교 | Pencil 스크린샷 vs 구현 스크린샷 |
| 토큰 사용률 | 100% 토큰 기반 (하드코딩 없음) |
| 빌드 | `npm run build` 성공 |
| 린트 | ESLint/TypeScript 에러 없음 |
| 상태 커버리지 | 모든 상태 구현 확인 |

**출력**: 검증 리포트

## 생성되는 폴더 구조

```
src/
├── styles/
│   └── tokens.css          # 디자인 토큰 (CSS 변수)
├── components/
│   ├── ui/                 # 기본 컴포넌트 (Button, Card, Input)
│   ├── layout/             # 레이아웃 (Sidebar, Header)
│   └── features/           # 기능 컴포넌트 (MetricCard 등)
├── lib/
│   ├── api/                # API 클라이언트
│   └── hooks/              # 데이터 fetching 훅
├── types/                  # TypeScript 타입
└── app/                    # Next.js 페이지
```

## 기술 스택

**기본 스택**:
- React 18+
- Next.js 14 (App Router)
- Tailwind CSS v4
- TypeScript
- React Query (선택)

**유연하게 변경 가능**: Vue, Electron 등 프로젝트 상황에 따라

## 문제 해결

### "디자인 토큰을 찾을 수 없음"
→ .pen 파일에 변수가 정의되어 있는지 확인

### "컴포넌트 인식 안 됨"
→ Pencil에서 해당 컴포넌트가 reusable로 표시되어 있는지 확인

### "시각적 불일치"
→ PASS 6 검증 실행 후 토큰 매핑 확인, 필요시 토큰 조정
